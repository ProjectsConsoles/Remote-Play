# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A small set of Steam Deck (SteamOS) client scripts that let a Steam Deck act as the
controller + display for Sony's official "Remote Play with PlayStation 3" software,
which normally only runs on Windows and only supports DualShock 3 via a real PS3 or
paired controller.

The actual pipeline spans two machines:

1. **Windows PC** — runs the patched Sony Remote Play client (see `Remote-Play.zip`,
   a third-party-patched build for non-VAIO PCs) which talks to the PS3 over the
   network. A server-side component (**not included in this repo**) must run on that
   PC to (a) receive the UDP joystick JSON from the Deck and inject it as virtual
   controller input into the Remote Play window, and (b) capture/encode the Remote
   Play video+audio and re-stream it as MPEG-TS over UDP.
2. **Steam Deck** — this repo. Reads the Deck's built-in controller with `pygame`,
   serializes its state to JSON, and sends it over UDP to the Windows PC at a fixed
   rate; separately plays the incoming MPEG-TS video+audio stream with `ffplay`.

There is no build system, package manifest, linter, or test suite — this is a couple
of standalone scripts, iterated on directly against real hardware.

## Files

- `input_client.py`, `input_client_v2.py`, `input_client_v3.py` — successive versions
  of the controller-input sender. **`input_client_v3.py` is the current/working one**;
  the earlier versions are kept for reference, not deleted dead code. Do not "clean up"
  by removing v1/v2 unless asked.
- `start_client_stream.sh` — launches `ffplay` to receive and display the combined
  video+audio UDP stream from the PC.
- `Remote-Play.zip` — the patched Sony Remote Play installer for the Windows-side PC
  (installer .exe, launcher .exe, patched DLL, and its own README with install steps).
  This is third-party binary content, not something to edit.
- `ps3rp-env/` — a Python venv (Python 3.13, `pygame`). Generated by `python3 -m venv`;
  never hand-edit files under it. `.gitignore` inside it excludes everything.

## Why there are three input client versions

Each version reflects what was empirically confirmed on real Steam Deck hardware,
because SDL reports a different button/axis layout depending on whether
`lizard_mode` is enabled:

- **v1** (`input_client.py`): dumps raw numeric axes/buttons/hats, no name mapping.
  Includes a `--test` mode for manually discovering what each index does.
- **v2** (`input_client_v2.py`): assumes the Deck's controller shows up as an
  emulated **Xbox 360 pad** (the default when `lizard_mode` is on), with a fixed
  `BUTTON_NAMES`/`AXIS_NAMES` mapping for that layout (hat-based D-pad).
- **v3** (`input_client_v3.py`): assumes `lizard_mode` is disabled
  (`/sys/module/hid_steam/parameters/lizard_mode` set to `0`), which makes SDL expose
  the Deck's **native** controller instead of the Xbox 360 emulation — different
  button indices, D-pad arrives as four separate buttons (16–19) instead of a hat,
  extra buttons (Steam, Quick Access, back grips L4/L5/R4/R5), and analog triggers on
  axes 8/9 instead of 4/5. v3 also falls back to synthesizing the D-pad from those
  button indices if no hat is present.

When editing controller mapping logic, check which `lizard_mode` state and SDL
mapping the target script assumes — v2 and v3 mappings are **not interchangeable**.
Button/axis indices in the `BUTTON_NAMES`/`AXIS_NAMES` dicts were confirmed by hand
against physical hardware, not guessed; verify against real hardware (or the
`--debug`/`--test` output) before changing them.

## UDP wire format

Sent by all input client versions as a JSON-encoded UDP datagram per tick:

```json
{"t": <unix timestamp>, "axes": {...}, "buttons": {...}, "dpad": {"x": -1|0|1, "y": -1|0|1}}
```

(v1 uses plain lists instead of named dicts for `axes`/`buttons`/`hats`.) There is no
receiving/server-side code in this repo to cross-check the format against — treat the
sender scripts as the source of truth for the protocol.

## Common commands

Activate the venv before running anything (or invoke its `python3` directly):

```bash
source ps3rp-env/bin/activate
```

List connected controllers:

```bash
python3 input_client_v3.py --list
```

Send controller input to the Windows PC (adjust `--host` to the PC's LAN IP; default
`--port` 9000, default `--rate` 60 Hz):

```bash
python3 input_client_v3.py --host 192.168.1.50 --port 9000 --debug
```

`--debug` prints every packet sent (pressed buttons, dpad, axis values) — use it when
verifying a button/axis mapping change.

Play the incoming video+audio stream (listens on UDP port 5000, hardcoded in the
script):

```bash
./start_client_stream.sh
```

Requires `ffplay` (e.g. `flatpak install org.freedesktop.Platform.ffmpeg-full`, or a
distro package).

There are no lint or test commands — verify changes by running the script against
real hardware and/or the live PC-side receiver.
